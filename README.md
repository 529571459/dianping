# 食单 · 单人版

一个人的吃喝记录本。每顿饭记下店名、点了什么、人均、照片，然后按味道 / 环境 / 服务 / 性价比四项打分，
加一句「还会再来吗」。没有服务器，没有账号，没有网络请求，数据全在你自己手机上。

---

## 怎么跑起来

1. 装 **Android Studio**（免费，官网下载，Mac 版选 Apple Silicon 那个）。
2. 打开 Android Studio → `Open` → 选中解压出来的 `Shidan` 文件夹。
3. 第一次打开它会自己下载 Gradle 和依赖，要几分钟，等右下角进度条走完。
   - 如果提示找不到 SDK，点它给的 `Install missing SDK` 按钮就行，会自动生成 `local.properties`。
4. 手机用数据线连上电脑，在手机上打开 **开发者选项 → USB 调试**。
   - 开发者选项藏在 `设置 → 关于手机 → 连续点七下版本号`。
5. Android Studio 顶部选中你的手机，点绿色的 ▶ Run。装完自己就启动了。

装上之后拔掉线也能用，它就是台正常的 app。不需要开发者账号，不需要上架，不花一分钱。

想给别人装，或者换手机：`Build → Build Bundle(s) / APK(s) → Build APK(s)`，
生成的文件在 `app/build/outputs/apk/debug/app-debug.apk`，发过去手动安装即可。

## 里面有什么

**记录页**
- 记一顿：店名、日期（有「今天/昨天/前天」快捷键）、人均、地点、点了什么、标签
- 四项打分 1–10 分，半分一档；再选一个「还会来 / 看情况 / 不来了」
- 可以先记下来不打分，卡片上会留个「还没打分」的入口，回头补
- 四项里最高最低差 3 分以上，卡片会标一句「评价两极」——这种店往往是"东西好吃但服务烂"

**照片**
- 拍照或从相册选，一条最多 9 张
- 进来自动压到长边 1600、JPEG 80%，一张一两百 K，几千张也塞得下
- 照片存在 app 私有目录，**不进系统相册**，所以不需要任何存储权限
- 列表卡片显示第一张当封面，点开可以左右翻、单张删

**想去页**
- 随手存想去的店
- 「今晚吃啥」从想去清单和你标过「还会来」的店里随机抽一个
- 去过了 → 一键转成记录，名字自动填好

**统计页**
- 吃了多少顿、去过多少家、平均人均、拍了多少张
- 你的平均分（附一句不太客气的评价）
- 打分最高的、回头率最高的、标了「还会来」的、反复点的菜

## 代码是怎么组织的

```
app/src/main/java/com/shidan/app/
  MainActivity.kt        入口，底部三个 tab，编辑页作为全屏覆盖层
  Models.kt              Visit / Rating / Wish 三个数据类 + JSON 读写
  Store.kt               全部数据一个 JSON 文件，Compose 直接观察
  Photos.kt              压缩、EXIF 转正、存取、删除
  ui/
    Theme.kt             配色（浅色 / 深色两套）
    Common.kt            照片异步加载、日期格式化、几个小组件
    LogScreen.kt         记录列表和卡片
    EditVisitScreen.kt   新增/编辑表单，相机和相册都在这里
    PhotoViewer.kt       全屏看图
    WishScreen.kt        想去清单
    StatsScreen.kt       统计
```

**为什么没用 Room（SQLite）**：一个人几百条记录，数据库带来的复杂度换不回任何东西，
而且少一个注解处理器就少一整类版本对不上的编译问题。真到几千条了再换，`Store.kt` 是唯一要改的文件。

**为什么照片存文件不存数据库**：图片进数据库是反模式，读写都慢。现在是文件名存 JSON、
文件躺在 `filesDir/photos/`，每次启动扫一遍没人认领的照片顺手删掉。

## 以后要加双人互通的话

数据结构已经预留好了，不用重写：

- 每条 `Visit` 都有 UUID 和 `updated` 时间戳 —— 合并时按 ID 配对、按时间戳取新的
- 评分是独立的 `Rating` 对象挂在 `Visit` 上 —— 加一个 `authorId` 字段就能变成"一条记录挂两份评分"，
  两个人各写各的，天然不会互相覆盖

真要联网的话，改动集中在 `Store.kt` 一个文件：把 `load()` / `persist()` 换成云端读写。
免费方案是 Supabase（免费档 500MB 数据库 + 1GB 图片存储）。

## 已知的边界

- 数据在手机本地。卸载 app 或清除数据会全部丢失。`allowBackup` 是开着的，
  换手机走系统迁移能带过去，但别指望它 —— 重要的话以后加个导出功能。
- 没有搜索。几百条以内翻着找不费劲，超过了再说。
- 日期是手输的（有快捷按钮）。没上日期选择器是因为 Material3 的 DatePicker 还是实验 API，
  为一个填日期的框引入不稳定的依赖不划算。
